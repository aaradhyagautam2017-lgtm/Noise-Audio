Metadata (rendered from the stored authored YAML)

Purpose

The white content block of an action sheet — presents a set of options or an input the user can act on, with a locked set of content structures.

Usage

Used as the content block inside an Action sheet (Action card + grey overlay). The agent first selects the variant structure that fits the content, then sets the header and button toggles.

Design intent

Provide a single, consistent surface for optional, skippable actions and selections, with a fixed library of content structures so option-presentation stays uniform across the app.

Anti-patterns

  • not-standalone Do not use the Action card on its own; it only exists inside an Action sheet (paired with the grey overlay).
  • no-invented-variants Do not invent new variant structures; the set is locked.
  • find-my-earbuds-scope Do not use the find-my-earbuds variant outside the Find My Earbuds case.

  • Agent order: first choose the variant structure that fits the content, then set the heading/content toggle, then set the number and type of bottom buttons.
usage_boundary
  • Use the Action card (within an Action sheet) when the action is optional and skippable (e.g. upload a profile image, set a birthday). For unavoidable actions the user cannot skip, use the Modal card / Modal sheet instead. (Mirror of the shared action-vs-modal rule.)
